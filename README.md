# Reflect: an AI journal coach that remembers you

Every day you write a few lines in your journal. Reflect reads each entry, keeps a long-term memory, and every week writes a review. The review checks last week's goal, points out patterns with the dates that show them, and gives you **one** small suggestion. The next week it follows up on that suggestion.

Term project prototype for MIT 1.125 Agentic Engineering.

## How it works

```
daily entry ──► 1. EXTRACT (LLM → JSON: mood, emotions, sleep, bedtime, activities, people,
                │              stressors, did you follow the active suggestion?)
                ├─► 2. REMEMBER (SQLite: entries, extractions, reviews, suggestions)
                └─► 3. ASK one follow-up question if something is missing (LLM)

every Sunday ──► 4. FIND PATTERNS (plain Python statistics over all history)
                 5. REVIEW (LLM writes the review; it may only cite computed patterns + dates)
                 6. SET GOAL: the new suggestion becomes the "active suggestion" that steps 1 and 3 track
```

Key design choice: the LLM does the reading and the writing, and the counting happens in plain Python. Because of that, a pattern like "5 of 5 low-mood days came after a late night" comes from the real data and can't be hallucinated.

## Quick start

```bash
pip install -r requirements.txt
cp .env.example .env          # then paste your OpenAI key into .env

python -m reflect.cli demo                     # 3-week demo journal → out/demo_report_openai.md
python eval/goemotions_eval.py --n 200         # emotion accuracy on GoEmotions → out/goemotions_openai.json
python data/make_test_journals.py              # 9 test journals with known answers
python eval/review_eval.py                     # does the weekly review get it right? → out/review_eval_openai.md
streamlit run app.py                           # web app for your own journal
```

`--backend mock` runs everything offline with no key. Mock mode is only a plumbing test: extraction returns the hand-written labels and the review is a template.

The model defaults to `gpt-4o-mini`. To change it, set `REFLECT_MODEL=<model>` in `.env`. The full 3-week demo uses about 35 calls, and GoEmotions with n=200 uses 10 calls. Both together cost a few cents.

## Data

| Data | What it's for |
|---|---|
| `data/demo_journal.json` | 21 synthetic entries from a fictional student, with hand-written gold labels. Used for the demo and to score extraction. Regenerate with `data/make_demo.py`. |
| [GoEmotions](https://github.com/google-research/google-research/tree/master/goemotions) test split | 5,427 Reddit comments labelled with 27 emotions + neutral (Demszky et al., ACL 2020). Downloaded automatically. |
| Your own journal | Stored locally in `reflect.sqlite`, never uploaded except to the LLM API call. |

## Evaluation

### Weekly review evaluation (`eval/review_eval.py`)

This checks whether the review's claims are actually supported by the journal. It uses three kinds of test journal (3 random seeds each, generated by `data/make_test_journals.py`, all with known answers):

| Kind | What's in it | A correct review… |
|---|---|---|
| `clear_pattern` | 21 days. Low mood occurs only after late nights, and late nights only follow deadline evenings | reports `sleep_mood` and cites only those dates |
| `missing_days` | Only 8 of 21 days have entries | says there isn't enough evidence and claims no pattern |
| `no_pattern` | 21 days; sleep, mood and activities are random and independent | claims no relationship |

Each week's review is checked for: the real pattern found, an honest "not enough evidence", false relationship claims, invented patterns, cited days that have no entry, cited days outside the pattern's evidence, and citation precision/recall.

Evidence rules in `reflect/agent.py`: at least 10 entries in total, at least 3 days on each side of a comparison, and a permutation test that passes after a Bonferroni correction over all comparisons. The review prompt may only name patterns that pass these rules, and must set `evidence_level: not_enough` otherwise.

Statistics layer over 50 random seeds each (gold labels): the clear pattern was found 50/50 times; no-pattern journals gave a spurious relationship in 4/50 (8%); missing-day journals gave none.

### Goal follow-up

Each weekly suggestion comes with a machine-checkable rule: `bedtime_before`, `sleep_at_least`, `activity` or `log_field`. Next week's review reports two things: whether the rule was met according to the data ("met on 4 of 5 weeknights"), and what the user said in their entries. To make follow-up detection scoreable, the demo keeps one scripted goal ("no deadline work after 12:30am on weeknights") from week 2 on, because the demo journal's hand labels assume that goal. Use `--free-goal` to let the model choose each week's goal instead.

Recurring stressors ("'midterm' came up 4 times") are reported as **observations**. They aren't relationship patterns, so they never make the evidence level "enough".

### Other checks

1. **Extraction accuracy:** compares the model's output with the hand labels on 21 entries (mood, sleep, bedtime, activities, people, goal follow-up). Printed at the end of `demo`.
2. **Emotion recognition:** measured on GoEmotions. Reports any-label match, top-1, sentiment-group accuracy and micro-F1. The majority-class baseline ("neutral") scores 0.33 any-label match.
3. **Real use:** 3 weeks on my own journal. Did the patterns feel true, and did I follow the suggestions?

## Not medical advice

Reflect is a self-reflection tool. If an entry suggests a crisis, the app suggests reaching out to someone you trust or to a professional.
